# cdk-excavator v0.1.1

Security maintenance release for JSON input validation. Updating from 0.1.0 is recommended.

## Changes

- Upgrade Zod to 4.6.7, addressing [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).
- Add bounded JSON reads and fail-fast collection validation to limit resource consumption on malformed or excessively large input.
- Bound validation diagnostics and redact input values and dynamic dictionary keys.

## Input limits and compatibility

JSON input is limited to 32 MiB, 1,000,000 values, 50,000 entries in each array or dictionary, and depth 64. Schema/rule directory inputs share the byte/value budget across their files. Inputs over these limits fail explicitly; split the selected scope when needed. The tool does not silently truncate input or overwrite existing output on validation failure.

Existing schema versions and valid output behavior remain unchanged within these limits, including resource selection, TypeScript/Python CDK drafts and offline reports. AWS access remains read-only; this update does not deploy or import resources.

## Standalone binary trust policy

- Windows x64 remains intentionally unsigned (`NotSigned`).
- macOS Apple Silicon and Intel remain ad-hoc signed, without Developer ID signing or notarization.
- Linux x64 has no platform code signature. Verify all downloaded binaries using `SHA256SUMS` before running them.

npm provenance is not an OS publisher signature. See the [v0.1.1 usage guide](https://github.com/MareTecreate/cdk-excavator/blob/v0.1.1/README.en.md) for supported scope and limitations.
